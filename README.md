# A11yBaseline

Инструмент проверки доступности нативных iOS-приложений: проходит приложение,
записывает, что произносит VoiceOver на каждом элементе, и на следующем релизе
показывает, что сломалось.

Состоит из двух частей, и разделение между ними — главное решение проекта.

**Обход бесплатен и открыт.** С iOS 27 Apple отдаёт `XCUIVoiceOverService`,
который возвращает произнесённое как значение функции, а Appium обернул это
в открытый код ещё в июне 2026. Конкурировать с бесплатным первоисточником
бессмысленно, поэтому обход здесь тоже бесплатный.

**Продаётся суждение.** Ответ на вопрос «а правильно ли это произнесено» не
отдаёт никто. Пустая подпись у кнопки, имя файла вместо описания, пять кнопок
с одинаковым текстом, надпись на кнопке, не совпадающая с озвучкой, —
это движок правил, и он растёт.

## Что уже работает

- Обход приложения и снятие реплик — **на любом Xcode**, через дерево
  доступности. Точность приближённая и честно помечена в базовой линии.
- Обход через настоящий VoiceOver — на Xcode 27, включается флагом
  компиляции `A11Y_VOICEOVER_API`.
- Семь правил с привязкой к EN 301 549 (клауза 11) и WCAG 2.2, у каждого —
  парный фрагмент кода «было → стало» на SwiftUI.
- Прогон встроенного `performAccessibilityAudit` и его находки **отдельным
  разделом** отчёта, с пометкой, что они бесплатны.
- Базовая линия в JSON с отсортированными ключами — лежит в репозитории
  и читается в код-ревью.
- Сравнение прогонов с разделением на регрессии и просто изменения.
- Отчёт в Markdown.

## Быстрый старт

Добавьте пакет в UI-тестовую цель и напишите один тест:

```swift
import XCTest
import A11yBaselineCore
import A11yBaselineXCUI

final class AccessibilityBaselineTests: XCTestCase {

    @MainActor
    func testBaseline() throws {
        let app = XCUIApplication()
        app.launch()

        let plan = WalkPlan(steps: [
            .init(screen: "Главный") { _ in },
            .init(screen: "Настройки") { app in
                app.buttons["settings"].tap()
            },
        ])

        let recorder = BaselineRecorder(app: app, source: AccessibilityTreeSource(app: app))
        let current = try recorder.record(plan: plan, appVersion: "1.4.0")

        let store = BaselineStore()
        let url = URL(fileURLWithPath: "Baselines/ios.json")

        guard let saved = try? store.read(from: url) else {
            try store.write(current, to: url)   // первый прогон: записываем эталон
            return
        }

        let diff = try BaselineDiffer().diff(baseline: saved, current: current)
        let report = MarkdownReport().render(
            baseline: current,
            findings: RuleRegistry.standard.run(on: current),
            diff: diff
        )
        try report.write(toFile: "a11y-report.md", atomically: true, encoding: .utf8)

        XCTAssertTrue(diff.isClean, "Доступность ухудшилась относительно базовой линии")
    }
}
```

## Что считается регрессией

Не всё подряд — иначе проверка станет красной на каждом релизе с новой
функцией, и её выключат через две недели.

| Изменение | Регрессия |
|---|---|
| Элемент перестал озвучиваться | да |
| Элемент исчез из обхода | да |
| Появилась находка уровня «серьёзно» и выше | да |
| Текст реплики переписан | нет |
| Появился новый элемент | нет |
| Элемент переехал в порядке обхода | нет, но показывается |

## Правила

| Правило | Что ловит | EN 301 549 |
|---|---|---|
| `empty-utterance` | Интерактивный элемент без подписи | 11.1.1.1 |
| `generic-label` | Подпись вида «Кнопка», «Untitled», «TODO» | 11.5.2.5 |
| `filename-label` | В подписи имя ресурса: `ic_close_24`, `IMG_2043` | 11.1.1.1 |
| `duplicate-label` | Несколько элементов звучат одинаково | 11.5.2.5 |
| `label-in-name` | Видимая надпись не входит в подпись — ломает управление голосом | 11.2.5.3 |
| `symbol-derived-label` | Подпись выведена из имени SF-символа: «Send» в русском приложении | 11.5.2.5 |
| `target-size` | Цель нажатия меньше 24 пт — **не в наборе по умолчанию**, см. ниже | 11.2.5.8 |
| `reading-order` | Порядок чтения расходится с расположением на экране | 11.1.3.2 |

## Проверено на живом прогоне

В `Examples/DemoApp` лежит приложение с намеренными дефектами и UI-тест,
который гоняет пакет на симуляторе. Прогон на iPhone 17 Pro, iOS 26:

```
4 находки, 0 ложных срабатываний
serious  symbol-derived-label  Подпись «Send» похожа на имя символа
serious  generic-label         Подпись «Кнопка» не описывает назначение
serious  filename-label        В подпись попало имя ресурса: «ic_close_24»
moderate duplicate-label       3 элемента звучат одинаково: «Подробнее»
```

Контрольный элемент, сделанный правильно, не попал в отчёт — это проверяется
отдельным утверждением в тесте, потому что ложная находка дороже пропущенной.

Прогон изменил сам продукт, и это стоит описать: он нашёл три ошибки,
которых не было видно на фикстурах.

**Правило размера цели убрано из набора по умолчанию.** XCUITest отдаёт для
SwiftUI-кнопки границы её содержимого, а не область нажатия: кнопка с явным
`.frame(minHeight: 44)` приходит как 20 пт. На таких данных правило давало
находку почти на каждой кнопке. Размер цели меряет встроенный
`performAccessibilityAudit` — у него есть настоящая геометрия, и в том же
прогоне он сообщил об этом сам.

**Появилось правило `symbol-derived-label`.** Кнопка без явной подписи
не остаётся немой: SwiftUI подставляет имя SF-символа, и в русском приложении
VoiceOver произносит «Send». Формально подпись есть, поэтому ни встроенный
аудит, ни правило пустой подписи такой элемент не ловят.

**Исправлен обработчик встроенного аудита.** Он возвращал «не обработано»,
и каждая находка Apple роняла тест.

## Ограничения, названные честно

- Обход через дерево доступности — **приближение**. Настоящий VoiceOver
  склеивает соседние элементы, сокращает длинные подписи и объявляет роли
  на языке пользователя. Базовые линии разной точности сравнивать нельзя,
  и пакет откажется это делать.
- Правило порядка чтения консервативно: срабатывает только на разрыве
  через три позиции и сообщает один раз на экран.
- Осмысленность подписи машина не проверяет. «Кнопка 2» пройдёт все правила.
  Это и есть граница между инструментом и суждением человека.
- Правило `label-in-name` требует, чтобы источник умел отличить видимый текст
  от подписи. В SwiftUI кнопка с заданной `accessibilityLabel` часто не отдаёт
  текстового потомка отдельным элементом, и тогда правило молчит. Молчать
  правильнее, чем гадать: ложная находка подрывает доверие ко всему отчёту.
- Правило размера цели включается отдельно через `RuleRegistry.withTrustedGeometry`
  и только если вы проверили, что в вашем приложении геометрия элементов
  соответствует области нажатия.
